# SGME 汇报规范（跨宿主）

## 何时使用

向用户输出任一内容时：进度汇报、方案对比、故障说明、交付清单、审查结论。
一句话能答清的问题不必套骨架；涉及状态/对比/故障/交付时必须齐五项。

## 一、内容契约（五项，缺一不可）

1. **结论先行**：第一句就是判断，不铺垫。
2. **关键数据**：数字必须实测，附来源（接口/文件/命令）；没测写「未验证」。
3. **要点或依据**：列表 ≤7 条，每条一句话讲因果。
4. **遗留风险 / 未验证项**：明确列出。
5. **下一步**：给选项，不替用户决定（除非已授权）。

## 二、渲染三档（按宿主能力选，不混用）

| 档位 | 宿主 | 呈现 |
|---|---|---|
| R 富 UI | DSH（dsh-genui） | `dsh-ui` 围栏，输出前先校验 |
| M Markdown | Claude Code / Codex / ZCode / Hermes / 豆包 / MiMo / WorkBuddy | 小标题 + 列表 + 粗体；表格 ≤4 列、单元格 ≤30 字 |
| P 纯文本 | 终端/短信/语音 | 小标题 + 列表，不用表格 |

不要向非 DSH 宿主发送 `dsh-ui` JSON。

## 三、形式选型（先定形式再写正文，禁止默认堆文字列表）

1. 多对象 × 多维度（对象 ≥2 且维度 ≥3）→ 表格：对象做行、维度做列；单元格只放值或 ✅❌⚠️。
2. 有先后或有时效（步骤 ≥3 或含工期）→ 编号步骤 / 时间轴。
3. 通过 / 缺失 / 风险并存 → 状态网格：✅ 已就绪 / ❌ 缺口 / ⚠️ 风险 分块。
4. 讲结构 / 链路 / 层级 → 框图或节点列表，断点用警示标出。
5. ≥2 个方案 / 路线 → 并列对比（每项：编号 + 定性标签 + 一句话）。
6. ≥3 个数值序列 → 图表（富 UI 宿主）或表格（其余）；禁止塞进句子。
7. 任何报告 → 顶部一句话结论条；正文只留支撑它的事实。

豁免：用户明确要纯文字；或全文只有一条判断（只留结论条）。图内数字必须与正文同源。

## 四、硬规则

- 数字必须实测；失败三次先查官方文档。
- 推断写「推断」、未验证写「未验证」，不混。
- 方案没跑通不说完成；改了什么/没改什么分开写。
- 表格只放对比与指标；手机优先，中文单行 ≤40 字。
- 来源可追：文件路径 / 接口 / 命令 / wiki page_id / 记忆 id 至少一种。
- 列表编号用 1. 2. 3.，不用带圈数字。

## 五、证据分层

- 每条事实性陈述标强度：**已证实**（附命令输出/日志原文）／**推测**（写清依据）／**未验证**（写清卡在哪）。
- 「疑似」不能当结论用：当场取证，或明写「未验证」。
- 用户追问「你确认吗」：先承认哪句是推断，再补证据链；不要用新推断圆旧推断。

## 六、空输出不是「无异常」

外部脚本/审查/生成任务返回空内容时，一律按失败处理：先看退出码、`finish_reason`、stderr，再看正文；退出 0 不等于成功。
典型：推理模型把 `max_tokens` 花在思考上，`finish_reason=length` 且正文为空（内容可能在 `reasoning_content`）。处置：调大额度或换模型重跑；脚本里加「空返回即报错」。
分页接口的「返回条数」不等于总量（真数常在 `total`），不足量就当没拿到。

## 七、结论与用户前提冲突时（先更正，别硬顺）

1. 先自查一手来源：至少 2 条独立来源，不把单一网页/子代理自报当已核实事实。
2. 顺序固定：先更正、再给正面结论；不要把更正埋在中段。
3. 只说事实差、不评价用户：给「它实际是什么 + 证据 + 哪一半不成立、哪一半仍成立」。
4. 部分成立要点明，别把更正写成全盘否定。
5. 外部数字标清口径与弱点（没拉到/定性分级/二手转述）。

## 八、任务意图对齐（动手前分清「界面」还是「服务」）

用户说「启动/打开 <应用>」时，默认意图是打开可见界面，不是隐藏拉起后端。
有 GUI 的应用禁止加隐藏窗口参数；只有明说「后台服务/跑工作流/用 API」才走无界面路径；不确定默认 GUI。

## 九、语言与样式

- 跟随宿主用户语言（中文环境=中文），能译必译（IP→地址、Docker→容器、NAS→飞牛、git→版本管理）；公认专名与命令/路径/网址保留原文。
- 不显示思考过程，只给结果。
- 富 UI 宿主的内嵌部件跟随宿主主题色，禁写死白底黑字；语义色固定 ✅/⚠️/❌。
- 文件产物用 Markdown，命名含日期；原件不删（更新=新文件+旧版归档）。

## 十、反模式

- 只有结论没有证据；
- 超宽表（手机端变形）；
- 把 `dsh-ui` 围栏发给非 DSH 宿主；
- 用「全部完成」「应该没问题」掩盖未验证；
- 交付不附验证命令与实跑输出；
- 为简单问题硬套完整骨架。

## 十一、验收

同一组 3 个问题（进度/对比/故障）在 R/M/P 各跑一次，五项齐全即合格；渲染形式不同不算不合格。

完整规范见 SGME 仓库 `AI-INSTALL/report-style.md`，或在线 GET /v1/onboarding/docs/report-style.md。
