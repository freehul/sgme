# 编码开发工作流

## 何时使用

需要写代码、改测试、修 Bug、重构、审查或提交时使用。只提供开发方法；SGME 架构细节、适配器细节和技能治理分别由对应技能提供。

## 工作闭环

1. **确认范围**：读项目规范、当前 Backlog 和相关设计；列出改动文件、依赖、验收标准。
2. **理解影响**：仓库存在 `.codegraph/` 时优先运行 `codegraph explore "<问题或符号>"`，再用 `codegraph affected <changed-files>` 找受影响测试；没有 CodeGraph 再用项目索引工具。
3. **TDD**：先写能复现需求或 Bug 的失败测试（RED），确认失败后做最小实现（GREEN），最后重构（REFACTOR）。
4. **调试**：先保存完整错误和复现条件；沿调用链定位根因，形成可证伪假设，一次只改一个根因并补回归测试。
5. **审查**：检查边界、异常、兼容性、权限、日志、秘密、路径可移植性和是否误删原件；代码与文档必须一致。
6. **验证**：先跑目标测试，再跑项目全量测试；执行项目配置的格式/lint 检查。没有新鲜输出证据，不宣称完成。
7. **提交**：按逻辑分组提交（commit），使用 `feat:` / `fix:` / `refactor:` / `test:` / `docs:` / `chore:`；多步骤任务按依赖拆成小提交或本地 PR 分支。

## 不可绕过的边界

- 原始会话、数据库、配置和用户数据只读；迁移、重建、清理必须在副本或明确目标上执行。
- 不把密钥、真实内网地址、个人身份信息或本机绝对路径写进代码、测试、文档和示例。
- 同一命令连续失败三次后停止盲试，升级到官方文档、Issue、社区资料，再重新评估方案。
- 不为了通过测试删除功能、降低安全性或吞掉异常；优先修根因。

## 最小验收清单

```text
□ 需求/设计/Backlog 已核对
□ 失败测试先于实现，回归测试已保留
□ 目标测试通过
□ 全量测试通过
□ lint/format 已执行并区分新增问题与既有基线
□ git diff --check 通过
□ 无秘密、无误删、无未记录的行为变化
```
