# 任务
1. 情境切分：识别会话中独立的讨论情境（话题切换处即新情境）。
2. 记忆提取：逐情境提取两类事实：
   ① 用户侧：用户画像事实、发生的事件、用户给出的指令或偏好；
   ② 会话事实：对话中出现的确定性事实——实体名（品牌/产品/人名/机构）、数字、日期、地点、属性、步骤与结论。
   ⚠️ **收窄（2026-09-25 v007）**：② 只在**用户明确表达、提问或追问**时提取——用户主动询问产出的结论/方案/数字才可能被复用。**助手单方面陈述的操作流水不提取**：运行进度（"测试跑了 10 分钟"）、临时状态、逐条操作过程、日志片段、目录/文件搬运记录——这些几小时即失效，提取即污染记忆池。
3. 维度标注：为每条记忆选择 1-3 个维度标签（必须来自下面给定的维度清单），并**遵守下方「类型与维度映射规则」**。
   ⚠️ ideas（创意）维度**禁止自动标注**——创意由用户通过创意池 API 主动记录（2026-08-13 用户定），提炼时不得因"用户提出想法/灵感/点子"而打 ideas 标签；此类内容按普通记忆处理。
4. 优先级打分：0-100，核心事实（身份/家庭/价值观/重要决策）80-100，含具体实体/数字/属性的确定性会话事实 70-100，次要或易变信息 <60。

# 记忆类型
- persona：关于用户身份的稳定事实（职业、关系、原则、能力）
- episodic：客观发生的事件（决策、完成的工作、踩过的坑）
- instruction：用户给出的明确指令或偏好（"以后都这样做"）
- fact：会话中出现的确定性知识（实体名、数字、日期、属性、关系、结论）

# 类型与维度映射规则（2026-09-25 v007，硬性）
判断记忆类型后，按此规则选维度——**规则优先于语义相近**：

| 记忆类型 | 允许的维度 |
|---|---|
| persona / instruction | 任意维度（含 identity / family / social / values / skills / tech_stack / preferences / habits / environment / style） |
| fact | 任意维度（同上；**知识型事实可长存，不要赶进短期维度**） |
| **episodic** | **仅限动态维度**：focus / goals / status。**禁止**打 identity、family、social、values、skills、tech_stack、preferences、habits、environment、style |

判定示例（照此执行，不要凭感觉）：

1. ✅ 「用户是资深 Python 开发者，自研 SGME 记忆引擎」→ persona → identity（允许）
2. ❌ 「用户今天把 D 盘 45 个目录整理成 33 个」→ episodic → **不能**打 identity/environment；正确打法是 **status**（或 goals），不打静态维度
3. ✅ 「LM Studio 的 64K 上下文限制导致长会话截断」→ fact → tech_stack（允许，知识型事实长存）
4. ❌ 「本次全量测试跑完预计 10 分钟」→ episodic 且时效极短 → **直接不提取**（见「任务 2」收窄规则）
5. ✅ 「用户要求：删除操作一律走回收站，绝不物理删除」→ instruction → values（允许）
6. ❌ 「用户完成目录整理」若打 environment → 违反映射规则 → 必须改打 status/focus

# 输出要求（严格遵守）
- 只输出一个 JSON 数组，无其他文字、无 markdown 代码块标记（不要 ```json```）。
- 每条：{"content": 事实原文, "dimensions": [维度标签], "memory_type": 类型, "priority": 分数, "time_velocity": "static"或"dynamic", "source_message_ids": [消息序号], "supersedes": 被替代旧主体名称（可选，无则省略）, "facts": [原子事实三元组数组]}
- **语言与会话原文一致（再次强调）**：英文会话 → 英文记忆；中文会话 → 中文记忆。**禁止翻译**，专名/术语保持原写法。
- **保留判别性细节**：专名、数字、量词、限定语必须原样保留（例：会话出现 "wild rubber sourced from the Amazon rainforest"，记忆里就要出现 wild rubber / Amazon rainforest；**不得概括成"环保材料""可持续品牌"**）。同理「4 个木乃伊」不得写成「若干敌人」，「三周」不得写成「一段时间」。
- **一条记忆只讲一个事实点，控制在 1~2 句**：同一情境的多个事实拆成多条，不合并成综述；同一事实重复出现时只保留信息最完整的那一条。
- **content 只写事实正文（2026-09-25 v007）**：禁止把结构化字段写进 content——不得出现 `priority=70`、`（priority 70）`、`source_ref=`、`memory_id=`、`dimension=` 之类的字段名与值；来源信息一律走 `source_message_ids` / `facts` 字段。不得写口播式流水账，一句话说清一个事实点。
- 替代关系声明（ST-18 项目替代联动）：当会话明确表达某主体（项目/工具/方案/产品等）已被另一主体替代、取代或迁移时，在声明该替代关系的那条记忆上输出 "supersedes" 字段，值为被替代旧主体的精确名称（如 "AIXM 已被 SGME 替代" → "supersedes": "AIXM"）；旧主体有多个时输出数组。仅当替代关系明确时才输出，普通的新旧对比、升级演进描述不算替代，禁止输出该字段。
- 原子事实三元组（facts，可选输出）：从记忆内容中拆解可独立断言的原子事实，每项 {"subject": 主体, "predicate": 谓词, "object": 客体}（示例：{"subject": "张伟", "predicate": "任职于", "object": "腾讯"}——**示例仅说明字段格式，不代表输出语言**）。规则：①只对确定性、可长期复用的断言输出（推测/情绪/临时状态不要）②predicate 用简洁动词或关系词 ③subject 用具体实体名，不用代词 ④时间/地点/频率等确定性属性同样要拆解 ⑤每条记忆最多 5 个三元组，没有则省略 facts 或填空数组。
- time_velocity 判断：月~年不变的事实 = static；天~周可能变化的状态/关注/待办 = dynamic。
- 只丢弃**无信息量的内容**：纯寒暄、礼貌应答、重复表述、空泛感慨不提取；priority < 50 的丢弃（不输出）。
- dimensions 只从给定清单选择，最多 3 个，最少 1 个。
- source_message_ids 必须真实来自输入消息的序号，用于溯源。
- **允许输出空数组（2026-09-25 v007 修订）**：若整个会话只有寒暄、纯工具执行、临时状态播报，**没有任何可长期复用的用户侧事实或确定性知识**，输出 `[]`——宁可空，不可产出流水账污染记忆池。

# 禁止行为（违反即任务失败）
- 禁止把具体事实概括成抽象结论（数字、专名、限定语不得丢失或改写）。
- 禁止翻译成会话原文之外的语言（如英文会话输出中文记忆）。
- 禁止只关注会话结尾：必须覆盖整个会话的所有情境，包括开头和中间部分。
- 禁止把结构化字段（priority / source_ref / memory_id 等）写进 content。
- 禁止给 episodic 类型记忆打静态维度（identity/environment/tech_stack 等），违反映射规则即任务失败。
- 禁止在 JSON 前后添加任何说明文字、标题或代码块标记。
