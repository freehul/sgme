## 定位与边界（架构铁律级）

SGME = **被动记忆引擎**：只发信号、只存记忆、只提供角色数据。
主动关怀（决策/触达）= **消费方 agent 的责任**（Hermes 等，SCSM 存在时由 SCSM 接管）。

业界验证（2026-08-13 调研 Mem0/Letta/Zep/Hindsight/TencentDB/OpenViking/C.AI/Replika/星野）：
记忆层与动作层分离是行业铁律——TencentDB 代码级把宿主 cron/heartbeat 会话当噪声过滤，
"记忆引擎拒绝主动"；SGME 的"信号总线 + 消费者"架构与 Zep webhook / TencentDB 同构。

## 三个决策点（2026-08-13 用户拍板）

1. **落地形态**：SGME 侧只做「信号增强 + 角色层数据结构」；关怀决策/触达全在消费方
   agent（Hermes 插件/cron 消费信号）。SGME 内核保持零决策、零推送通道。
2. **角色文件格式**：Character Card V2 兼容子集（name/description/personality/scenario/
   first_mes/mes_example/system_prompt/post_history_instructions/character_book +
   extensions 命名空间挂关怀策略自定义字段）。可移植、生态兼容。
3. **零物化例外**：用户画像保持模板查询零物化（架构铁律不变）；**角色 persona 允许
   物化文件**（一次生成、稳定注入，省 token）——角色是皮，物化无妨；芯（记忆池）
   保持零物化。

## 分层架构

```
┌─ 消费方 agent（Hermes 等）──────────────────────────┐
│  cron 定时 + heartbeat 巡检 → 消费信号 → 关怀决策    │
│  （默认静默 / 幂等去重 / 冷却期 / 送达确认）          │
│  角色 persona（物化文件）→ 沟通外皮                  │
└───────────────┬──────────────────────────────────────┘
                │ 读：检索/注入        │ 写：对话后提炼（既有管线）
┌───────────────▼──────────────────────────────────────┐
│ SGME 内核（被动）                                     │
│  信号总线 signal_events（已有 2134 条，加关怀信号类型）│
│  记忆池（标签化，零物化画像 = 模板查询）               │
│  角色层数据结构（角色卡文件 + 角色 persona 物化）      │
└──────────────────────────────────────────────────────┘
```

## 关怀信号（SGME 侧增强）

现有 signal_events（memory_updated 等）已够用；按调研补充信号类型（T-36 定义）：

- 事件驱动：记忆新增/冲突裁决/高情绪标签（提炼时打 status/focus 等维度，情绪信号源）
- 时间驱动：待办到期（tasks 维度 + TTL 边界）、每日关怀扫描（与 Dream 定时器协同）
- 状态驱动：目标矛盾检测输入（goals/values 维度交叉）、过度工作预警（作息节奏模式）

触发策略抄业界作业：默认静默；MemGPT 式"显式请求才继续"；last_notified_at 幂等去重；
情绪信号冷却期；无回应指数退避（Nomi）。

## 角色层设计（皮）

- 角色文件：Character Card V2 兼容子集，存 `roles/` 目录（不入 git 的可用户自定义区
  或项目内模板区，实施时定），extensions 挂关怀策略（问候模板/触发规则/频率档位）
- 角色 persona：物化文件（LLM 生成），生成方法论借鉴 TencentDB Persona Architect
  四层深度扫描（事实锚点→兴趣图谱→交互协议→认知内核），≤2000 字、禁推测、增量更新
- 换皮不换芯：换角色 = 换 persona 文件 + 表达风格 + 主动策略；记忆池不动
  （差异化卖点：C.AI 角色记忆不共享 / Replika 单伴侣 / 星野羁绊 RAG 的硬伤）
- 记忆双向流动：角色读记忆（注入/检索已有）+ 写记忆（对话后提炼沉淀已有管线）
