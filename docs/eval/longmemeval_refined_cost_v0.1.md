# LongMemEval refined 臂全量成本评估 v0.1

> 2026-09-02 | 基于同机同链路实测微基准（20 session）+ 数据集全量静态模拟
> 结论先行：**500 题全量 refined ≈ 8.5~12.5 天连续运行（免费链、串行），API 费用 ¥0，最大风险是长周期中断。**

## 2. LLM 调用量（静态模拟 + 实测校准）

- **L1 提取**：回合感知分块（chunk_size=5000/min 4500）→ 全量 **53,386 块**，均值 2.13 块/session。
- **L1.5 冲突裁决**：随库内记忆累积出现（前 5 session 为 0，20 session 实测新增 ~1.3 次/session）。
- 实测校准：**3.45 calls/session**（20 session，0 错误）→ 全量 ≈ **86,600 次 LLM 调用**。
- QA 阶段（answer + judge）：500×2 = 1,000 次，量级可忽略。

## 3. 实测微基准（同机，agnes-2.5-flash 免费链，20 session）

| 指标 | 实测值 |
|---|---|
| per-session 耗时 | **mean 42.6s / median 28.7s**（max 239s，离群为免费档慢响应） |
| per-call 耗时 | ~12.3s（推理延迟为主） |
| tokens/call | prompt 3,582 / completion 949 |
| 记忆产出 | 4.45 条/session |
| throttle 等待 | **0s** —— 单次推理 8s+ > 0.5rps 的 2s 间隔，令牌桶永不空 |
| 错误 | 0 |

关键洞察：**瓶颈是免费档推理延迟，不是 0.5rps 节流**。这意味着并发加速不会被自家 throttle 拦住（2~3 路并发折算 15~23 req/min，仍在 agnes 免费 RPM 20~30 边界内）。

## 5. 加速与折中方案

| 方案 | 预计总时长 | API 费用 | 前提/风险 |
|---|---|---|---|
| A. 串行现状 | 8.5~12.5 天 | ¥0 | 需先补断点续跑；Windows 更新/休眠是主要中断源 |
| B. 并发 2 路 | ~4.5~6.5 天 | ¥0 | RPM ~15/min，安全；需小改 runner 支持线程池 |
| C. 并发 3 路 | ~3~4.5 天 | ¥0 | RPM ~23/min，贴 agnes 上限；429 重试会拉长尾 |
| D. DeepSeek-V4-Flash + 并发 4 | ~1.5~2 天 | ~¥580 | 付费档稳定低延迟（~2-3s/call）；B144 纪律需用户显式解禁 |
| E. 分层抽样 100 题（每题型 ~17） | 2~2.5 天 | ¥0 | 置信区间变宽（±5pp 量级），不适合发榜，够内部迭代 |
| F. 分层抽样 180 题 | 3.5~5 天 | ¥0 | 平衡点；题型覆盖与全量一致 |

## 6. 建议（决策点）

1. **不建议直接跑方案 A**：12 天无断点续跑 = 赌 12 天运气；先花 0.5 天给 `longmemeval_eval.py` 加 per-question checkpoint（每题完成即落盘，重跑跳过已完题），这是所有方案的地基。
2. **推荐 B（并发 2 路 + 断点续跑）**：~5 天、¥0、风险可控，与 NAS 部署互不干扰（评测走笔记本临时库）。
3. 若要出**对外可引用的榜单数字**，建议 C 或 D 换取全量；若只为**内部迭代 T-149**（原 T-142，2026-09-03 改号；时序/跨会话聚合补齐），方案 E/F 的抽样已足够定位问题。
4. 无论哪档：跑前先确认 agnes key 有效（本次实测曾因 SGME_HOME 重定向出现全量 401 的假象）+ 计划任务防休眠。
