# 记忆系统「Agent 接入与调用」横向对比

> 日期：2026-08-22
> 背景：SGME 为接入的 agent 专写了 `docs/agent-onboarding.md`（机器可读接入指引 + `agent_onboarding` 发现工具 + `self_config` 自助配置），本调研对比主流记忆系统如何处理「agent 接入这一步」与「agent 如何调用记忆」，以判断 SGME 的接入引导是特例还是行业常态。
> 方法：SGME 部分基于本地源码/文档（`docs/agent-onboarding.md`、`sgme/`）；外部系统基于官方文档/SDK 实测片段（2026-08-21 检索）。

## 0. 一句话结论

**SGME 是所对比系统中唯一为「agent 接入」专门写了机器可读引导 + 自发现工具的系统。** 其余系统的「接入」要么外包给人类开发者读 SDK/README（Mem0 / Zep / LangMem），要么把记忆内建于框架（Letta），要么标准化为 MCP 工具但把「怎么用」丢给一段建议 system prompt（MCP memory server），要么根本不存在外部 agent 接入概念（DeepTutor，记忆是其内部模块）。

这印证了一个判断：SGME 的「接入引导」是一种**相对独特的设计取向**——不是把接入当「人读文档后接线」，而是把接入当「agent 连上后自助完成」。

## 1. 对比维度定义

| 维度 | 含义 |
|---|---|
| 接入形态 | agent 用什么平面连进来：SDK client / MCP server / framework-native / 内部 facade |
| 接入引导 | 是否有**写给 agent 读的**接入指南（而非只给人看的 README） |
| 自发现 | agent 连上后能否**自助获取**版本/能力清单/上手路径（无需人读文档） |
| 调用方式 | agent 实际怎么读写记忆：工具 / SDK 方法 / 注入 system prompt |
| 多体隔离 | 多 agent / 多用户如何区分数据边界 |
| 提炼触发 | 记忆的抽取/合并由谁、何时触发 |

## 2. 总对比表

| 系统 | 接入形态 | 接入引导(给agent) | 自发现机制 | 调用方式 | 多体隔离 | 提炼触发 |
|---|---|---|---|---|---|---|
| **SGME** | MCP(:9913) + HTTP(:9910) | ✅ `agent-onboarding.md` + `agent_onboarding` 工具 | ✅ `agent_onboarding()` 返回 29 工具清单 + 3 条主线 + `self_config` | MCP 工具 / HTTP：`append`·`inject`·`search`·`refine_*`·`signal_*` | ✅ 每 agent 独立 `agt_*` Key（register 签发）+ `session_key` | agent 会话结束 `refine_trigger(async)` + 服务端 `batch_scan` 兜底 + hooks 型适配器 |
| **DeepTutor** | 内部 facade（无外部 agent 接入） | ❌ 无（agent 是其内置组件） | ❌ | `read_memory`/`write_memory` 工具 + `MemoryStore` 外观 + `memory_references` 开关按需注入 | ContextVar 切 owner path（partner 隔离） | 前端 workbench 手动触发 consolidate（异步长任务 + 预览-应用） |
| **Mem0** | SDK client（`MemoryClient`/`AsyncMemoryClient`） | ❌ 只给人看的 SDK docs/quickstart | ❌ | SDK 方法 `add`/`search`/`get_all`；`@function_tool` 包装成 agent 工具 | `user_id` + `metadata` filters（task_id/session_id） | 服务端自动（add 时抽取/去重/更新） |
| **Zep** | SDK client（`ZepClient`/`AsyncZep`） | ❌ SDK docs + 框架集成示例 | ❌ | SDK 方法 `memory.add`/`get`/`search_sessions`；或框架集成类（如 `ZepAutoGenMemory`） | `user_id` + `session_id` | 服务端自动（add 时异步做图抽取 + 摘要 + 时序标注） |
| **Letta (MemGPT)** | framework-native（agent 即服务） | ❌ 框架文档（agent 模型自带记忆观） | ❌ | agent 自带 memory 工具：`core_memory_append/replace`·`archival_memory_insert/search`·`conversation_search` | `agent_id`（server-side stateful，DB 持久） | `sleep-time compute`（异步后台）+ agent 主动工具编辑 |
| **MCP memory server** | MCP server（`@modelcontextprotocol/server-memory`） | ❌ 只给配置说明 + 一段建议 system prompt | ❌ | 9 个 MCP 工具：`create_entities`·`add_observations`·`read_graph`·`search_nodes`… | ❌ 单 `MEMORY_FILE_PATH` JSONL，无内置多用户隔离 | ❌ 无自动提炼（扁平 JSONL，工具直写） |
| **LangMem** | 工具函数（`langmem`）接 LangGraph store | ❌ SDK docs + quickstart | ❌ | `create_manage_memory_tool`/`create_search_memory_tool` 包装成 agent 工具 | `namespace` | 后台 `memory manager` 自动抽取/合并/更新 |

## 3. 各系统「接入这一步」详解

### 3.1 SGME —— 接入即自助（行业特例）
- 三层发现：health 探测 → `~/.sgme/install.json` → 报告「未发现」。
- 连上第一件事调 `agent_onboarding()`：返回版本、**全部 29 工具清单与用途**、3 条主线（注册/提炼/回忆）、**`self_config` 自助段**。
- `self_config` 要求 agent **自己改自己的身份文件**（SOUL.md/AGENTS.md/CLAUDE.md），写入 `SGME-ONBOARDING-v1` 标记——SGME 不替 agent 改文件，只要求结果。换 Agent 零成本。
- 五条铁律 + 三档适配（hooks 型/自律型/保底型）+ 事件对接（SSE/signal_pull）。
- **特点**：接入引导是「机器可读 + 自发现 + 自助配置」，而非「人读 README 后接线」。

### 3.2 DeepTutor —— 记忆是内部模块，无外部接入概念
- agent 通过 `get_memory_store()` → `MemoryStore` 外观调用；对外只暴露 `read_l3_concat()`（读）/ `emit()`（写 L1 trace）/ `write_preference()`（写 L3 偏好）/ `update_l2/update_l3`（触发提炼）。
- 读取靠 `memory_references` 开关**按需注入** system prompt，或 `read_memory` 工具主动读。
- 写入只有 `write_memory` 一条窄通道（只写 `preferences.md`，写入前 `emit` L1 trace + 去重）。
- 提炼由前端 Memory workbench 手动触发，agent 不负责。
- **特点**：记忆紧耦合于产品内部，不存在「外部 agent 怎么接入」的问题。

### 3.3 Mem0 —— SDK 直连，接入=装包+Key
- `pip install mem0ai` → `MemoryClient(api_key=...)`。
- 调用是普通 SDK 方法：`client.add(messages, user_id=...)` / `client.search(query, filters=...)` / `client.get_all(...)`。
- 想让 agent 用，用 `@function_tool` 把 `add/search/get_all` 包成 OpenAI Agents SDK 工具——**接入引导完全由开发者在代码里写**，Mem0 不提供 agent 侧引导。
- **特点**：接入 = 人类开发者消化 SDK + 自己包工具函数。

### 3.4 Zep —— SDK + 框架集成类
- `pip install zep-python` → `AsyncZep(api_key, base_url)`。
- 调用：`client.memory.add_memory(session_id, messages)` / `get` / `search_sessions`。抽象是 user/session/message 一等公民。
- 框架集成通过**适配器类**而非引导文档：如 `ZepAutoGenMemory(zep_client=..., session_id=..., max_tokens=..., relationship_depth=...)` 直接替换 AutoGen 默认存储。
- **特点**：接入 = 选 SDK 或框架集成类，无 agent 自发现。

### 3.5 Letta (MemGPT) —— 记忆即框架
- 记忆不是「外部系统」，而是 agent 框架的内建能力。创建 agent 时给定 `memory_blocks`（persona/human/自定义）。
- agent 在自身 loop 里用自带的 memory 工具管理记忆：`core_memory_append/replace`（改常驻块）、`archival_memory_insert/search`（外部长期库）、`conversation_search`（召回历史）。
- `sleep-time compute`：异步后台 agent 在空闲时整理核心记忆（抽象、消歧、预计算）。
- **特点**：接入 = 用框架建 agent；记忆系统是「操作系统」而非「外设」。

### 3.6 MCP memory server —— 标准化工具，但无引导
- 配置 `claude_desktop_config.json` / `mcp.json` 即可，暴露 9 个 MCP 工具（实体/关系/观测的 CRUD + `read_graph`/`search_nodes`/`open_nodes`）。
- 存储是单 `MEMORY_FILE_PATH` JSONL 文件；**无内置多用户隔离、无自动提炼**。
- 官方只给一段「建议 system prompt」告诉模型何时建实体/加观测——**怎么用靠这段 prompt，不靠接入引导机制**。
- **特点**：接入形态最接近 SGME 的 MCP 平面，但**缺发现工具与自助配置**，把「如何用」外包给 prompt。

### 3.7 LangMem —— 工具函数接 LangGraph store
- `pip install -U langmem`，把 `create_manage_memory_tool`/`create_search_memory_tool` 挂到 LangGraph agent，绑 `InMemoryStore`（或 LangGraph Platform 长存 store）。
- 后台 `memory manager` 自动抽取/合并；另有 prompt 精炼工具。
- **特点**：接入 = 框架生态内的工具接线，无独立 agent 引导。

## 4. SGME 接入引导的独特点（对照总结）

| 能力 | SGME | 其他系统 |
|---|---|---|
| 机器可读接入指南 | ✅ `agent-onboarding.md` 写给 agent 读 | ❌ 全为人读 README/SDK docs |
| 连接即自发现 | ✅ `agent_onboarding()` 返回能力清单 + 上手主线 | ❌ 无（Mem0/Zep/Letta/LangMem/MCP） |
| agent 自助配置身份 | ✅ `self_config` 写身份文件 + 读回验证 | ❌ 不存在该概念 |
| 多档适配（hooks/自律/保底） | ✅ | ❌ |
| 事件主动唤醒（SSE/signal_pull） | ✅ | ⚠️ Zep 有事件流但非关怀闭环；其余无 |
| 写入纪律（五条铁律/格式校验） | ✅ | ⚠️ 各系统有软约定，无强制纪律 |

## 5. 可选借鉴（方向，非既成结论）

> 本节为「SGME 可参考的外部做法」，与第 4 节「SGME 已领先」互补；均为候选，未经 SGME 架构核对。

1. **Mem0 的 `function_tool` 包装范式**：把记忆读写包成标准 agent 工具函数（add/search/get），框架无关。SGME 的 MCP 工具已等价，但若要接 OpenAI Agents / AutoGen 等生态，可参考此包装层。
2. **Letta 的 `sleep-time compute`**：异步后台 agent 在空闲时整理核心记忆（消歧/抽象/预计算），与 SGME 的 `batch_scan` 兜底同源但更主动——SGME 可参考「空闲期主动重组」而非仅「status=new 触发」。
3. **Zep 的框架集成适配器类**：`ZepAutoGenMemory` 这种「一行替换某框架存储」的模式，比「暴露原始工具」对框架用户更友好。SGME 已有 Hermes/DSH 官方适配器，可参考其「适配器即类」的封装粒度。
4. **MCP memory server 的标准化工具面**：其 9 个 CRUD 工具命名极简、跨客户端通用——SGME 的 MCP 工具面可对照精简/对齐命名，降低新 agent 的理解成本。

## 7. 结论

SGME 把「agent 接入记忆系统」设计成**可机器执行的自助流程**（发现→连接→自发现→自助配置→纪律），在对比的 7 个系统中是**唯一**做到这点的。其余系统把这个环节外包给：人类开发者读文档（Mem0/Zep/LangMem）、框架内建（Letta）、或一段建议 prompt（MCP memory server），DeepTutor 则因记忆是内部模块根本不存在该环节。

这种差异本质是**设计哲学选择**：SGME 把 agent 当作「需要被引导接入的一等公民」；多数系统把 agent 当作「人类开发者接线后的调用方」。SGME 的接入引导值得保留并作为差异化优势；可选借鉴集中在「生态包装范式（function_tool / 适配器类 / 标准化工具命名）」与「主动式后台整理（sleep-time compute）」两个方向。
