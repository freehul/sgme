## 维护规则

1. **立项即建**：新项目创建本文件（Backlog），后续一直存在
2. **需求来源登记**：新 Story 标注来源（灵感/对标/痛点），Epic 标注方向
3. **拆解**：Story 成熟后拆成 Task/Bug（拆解 = 设计分析的一部分），全部 Task 满足 AC = Story ✅
4. **设计依附**：设计文档声明解决哪些 Story/Task → 反向登记到索引表
5. **完成即标记**：✅ + 版本，**不删除条目**；commit/PR 引用编号（Closes ST-x / T-x）
6. **未解决即任务**：🔴 = 当前任务池；🟡 = 暂缓；✅ = 已解决
7. **版本基准**：2026-08-28 版本升 1.1.0 起，新登记条目版本号写 v1.1.0（及以后更高）；历史 v1.0.1 条目保留不回改
