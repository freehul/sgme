# SGME 笔记本裸部署验证（2026-09-01）

> **类型**：新用户（first-time user）视角，非 Docker 直装
> **环境**：Windows 11 笔记本 · Python 3.13.14（独立 venv）· git 2.55 · NSSM 已装
> **隔离措施**：干净 `git clone` 副本 · 独立 `SGME_HOME` · 隔离端口（9910 / 9920 / 9930 / 9931）· 独立数据库（不碰生产库）
> **版本**：SGME v1.1.3
> **结论**：**源码部署（clone + `pip install -e .[dev]`）链路完整可用，核心能力全通**；但 **`pip install .` 打包分发路径完全不可用（P0 阻断）**，另有 **4 项 P1 级新用户体验缺口**

## 3. 问题清单

### P0-1 ❌ `pip install .` 打包分发完全不可用（阻断级）

**现象**：wheel 安装后启动立即崩溃

```
FileNotFoundError: 配置文件不存在: D:\...\venv-wheel\Lib\site-packages\config\llm.yaml
  at sgme/config.py:379 (_read_yaml)
  ← config.py:401 (load_llm_config) ← config.py:936 (load_config) ← app.py:590
```

**根因**：`sgme/config.py` 用 `PROJECT_ROOT = Path(__file__).resolve().parent.parent` 定位程序资源；wheel 下 `PROJECT_ROOT` = `site-packages`，而 `pyproject.toml` 明确排除资源目录且未声明 package-data：

```toml
[tool.setuptools.packages.find]
exclude = ["tests*", "scripts*", "docs*", "config*", "registry*", "templates*", "prompts*"]
```

实测 wheel 内 `sgme` 包 **0 个 `.yaml`/`.txt`**，`site-packages` 下 `config/` `registry/` `templates/` `prompts/` **全部缺失**。

**影响**：
- 未来发布到 PyPI 必崩（`pip install sgme` 直接用不了）
- README「打包分发时项目目录即完整交付物」只在源码分发下成立
- Docker 部署不受影响（Dockerfile 用 `COPY sgme/ sgme/` + 源码布局）

**建议修法（三选一，需拍板）**：
1. **资源内迁（推荐）**：把 `config/registry/templates/prompts` 迁到 `sgme/resources/` 包内，`PROJECT_ROOT` 保留源码回退；配 `package-data` 声明
2. **package-data + MANIFEST**：保持目录结构，改用 `data-files`/`package-data` 把资源打进 wheel
3. **代码兜底**：`PROJECT_ROOT` 找不到资源时按三级回退（包内 → `~/.sgme/` → 项目 CWD）

### P1-1 ⚠️ 未配 LLM 密钥时「静默空转」

**现象**：见 §2.3。产品完全不可用但无提示。

**证据**：无密钥启动日志**只有**默认 key 告警，**没有任何模型 key 缺失告警**：

```
[SGME auth] 警告：使用默认 admin key（dev-admin-key-change-me）…
[SGME auth] 警告：使用默认 agent key（dev-agent-key-change-me）…
（无 LLM 相关告警）
```

`health.missing_keys` 其实写得很详尽（含免费 Key 申请链接），但**只有主动调 `/v1/health` 才能看到**。

**建议**：
- 启动时打印模型 key 缺失告警（指向 `docs/guide/免费模型Key申请指南.md`）
- refine 全链失败时，在 `inject`/`search` 空结果响应里回带引导（如 coding/work 模式已有空态 note，可复用该机制）

### P1-2 ⚠️ 裸部署无 WebUI，文档未说明

**现象**：`/`、`/ui`、`/app` 全部 404。

**影响**：README 用了 9 张 WebUI 卖点图 + 「WebUI（含在镜像内）」表述，但裸部署用户拿不到界面。需 `cd ui && npm ci && npm run build` 生成 `ui/dist`，README 快速开始未提。

**建议**：README「快速开始」增补可选步骤「需要 WebUI？先构建前端（需 Node）」，并说明裸部署默认纯 API/MCP。

### P1-3 ⚠️ 空库首次启动即报「提炼停摆」

**现象**：全新库、从未提炼过，`/v1/health` 返回：

```json
"refinement": {"stalled": true, "heartbeat_ok": false, "last_refined_at": null}
```

**影响**：新手第一眼看到 `stalled=true` 会以为装坏了（实测提炼一次后 `stalled=false`）。

**建议**：`last_refined_at IS NULL`（从未提炼）时不判停摆，改为 `stalled=false` + 状态 `never_refined`。

### P1-4 ⚠️ refine 业务失败用 HTTP 200 返回

**现象**：`POST /v1/admin/refine/trigger` 全链失败时返回 **HTTP 200**，失败信息在 body 里（`status=error`）。

**影响**：客户端/脚本只查状态码会误判成功。

**建议**：业务失败用 HTTP 502/503（或至少 4xx），body 保留详情；或在文档显著标注「必须校验 body.status」。

## 6. 复现命令（本验证所用）

```bash
# 1. 干净副本 + 独立环境
git clone <repo> sgme-fresh/src
cd sgme-fresh/src
python -m venv ../venv
../venv/Scripts/python.exe -m pip install -e ".[dev]"   # 卡 SSLEOFError 时加 -i https://mirrors.aliyun.com/pypi/simple/

# 2. 启动（独立端口 + 独立数据目录）
SGME_PORT=9910 SGME_HOME=D:/tmp/sgme-fresh/home ../venv/Scripts/python.exe -m sgme

# 3. 验证
curl http://127.0.0.1:9910/v1/health
# MCP：http://127.0.0.1:9913/mcp（需 X-API-Key）

# 4. wheel 打包验证（当前必崩）
python -m venv ../venv-wheel
../venv-wheel/Scripts/python.exe -m pip install .
cd /somewhere/else && ../venv-wheel/Scripts/python.exe -m sgme
```
