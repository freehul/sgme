## 一、总体评价

**✅ 0.4 是一版高质量、可直接进入编码的架构设计；10 份详细设计内部自洽、与 0.4 决策一致。**

0.4 在三个层面上做对了硬事：

1. **修对了 0.3 的真实矛盾**——数据流三方矛盾（§8 写入路径 / 分层映射 / §3 模块定义对"记忆池输入方"各执一词）统一为「L1 产记忆（Memory DB）、L2 产场景（Wiki 精炼层）、画像 = 记忆池模板查询」，这是 0.3 最大的数据流硬伤，闭环干净。
2. **time_velocity 定稿比 0.3 二轮更准**——0.3 二轮把 time_velocity 说成"可选时间窗过滤条件"，混淆了「变更频率」与「时间新旧」两个概念。0.4 拆对了：`time_velocity ∈ {static, dynamic}` 是**频率元属性**，按新旧过滤另设显式 `time_window`。**这是对 0.3 二轮表述的正确修正，本审查明确采纳。**
3. **三轮修订加了多个 0.3 未覆盖的架构级改进**——信号引擎收缩为纯事件发布器（移除 care_candidate/due_reminder，行动决策归 Agent）、L0 自持 MD 文件（Hermes DB 非唯一溯源副本）、TTL 起算 updated_at + 续期、L2 纯记忆输入（底座源码调研定案）、双画像让位演进、快照分层 + 冷归档。

0.3 两轮已锁的决策（标签过滤 AND/OR 三处对齐、模式 A 判等锚点 memory_id、⑮ 技术栈归静态）在 0.4 中均标「延续」保留，未被推翻。

详细设计 10 份整体扎实：数据模型（memory_tags 关联表 + TTL 起算 updated_at + 溯源三段链 + scene_versions + git/非 git 版本管理边界）、接口契约（9910/9911 端口、/v1 append/inject/search/memory/events/health、Bearer+X-API-Key 分层、错误码）、模板引擎（id 引用 + 继承 + 校验 + 默认排序）、LLM 降级链（上下文预算公式 + 模型白名单 + rule 兜底）、提炼提示词（三套 + 模板变量 + 输出校验）、L0 文件格式（frontmatter + 原子追加 + 冷归档）、维度归一化（阈值 0.85 + 统计告警 + 注册表→提示词联动）、维度注册表/别名表（id/display_name + TTL 默认值 + 边界对照）——均可落地。

**结论：方向与结构无问题，可进编码。但交叉比对发现 2 处文档间矛盾（🔴）会在实现时立刻绊脚，另有 8 处一致性小修（🟡）建议顺手对齐。**

## 二、确认项（0.4 相对 0.3 的改进，值得肯定）

一、**数据流统一**（§8）：L1→Memory DB、L2→Wiki 精炼层、画像=模板查询，消除三方矛盾，且 §2 新增原则 14「提炼单向、溯源反向」把单向数据流上升为架构约束。
二、**time_velocity 定稿**（§8.1/§8.2）：频率 vs 时间窗分离，枚举收为 static/dynamic，删除无定义的 `slow`。
三、**模板查询回归纯结构化 SQL**（§8.2/§10）：FTS5/向量仅用于 /search（Tier 2/3），不再混入模板查询——避免实现者造无用索引。
四、**Tier 0 摘要生命周期**（§8.2）：固定每日 1 次 + 缺失/过期（>48h）降级静态维度直出，闭环了 0.3 未定的频率与降级路径。
五、**维度标注治理**（§9.1 + 归一化文档）：别名表 + 相似度兜底 + 未知丢弃告警（不自动注册）+ 注册表→提示词动态联动，落地了 0.3 留下的维度 id 治理问题。
六、**freshness 升级为 TTL 决策**（§8.2）：状态 7d / 关注·待办 30d / 其他动态 90d、起算 updated_at、update/merge 续期、过期退出注入但保留溯源——比 0.3 的"待办"更落地。
七、**信号引擎收缩**（§3/§11.1/§15）：SGME 只发数据/健康事件，行动决策归 Agent——与「SGME 纯数据不执行」原则更自洽。
八、**§9.3 上下文约束分层**（§9.3）：窗口值随模型动态读取（64K 是本地默认而非常量），并补充云端模型的成本+窗口共同决定批量。
九、**L0 自持文件 + 快照分层 + 冷归档**（§8/§17）：原始层独立于来源 Agent 存储，快照日增量/周全量/月归档 + >90 天 zstd 冷归档，控制了无限增长下的备份膨胀。
十、**§14 编号重排**（1–33）：消除 0.3 二轮补录引入的「#11 冲突」「#17 不存在」问题。

## 三、必须对齐（🔴 文档间矛盾，动工前必修）

### 1. L1.5 候选池「截断 vs 不截断」自相矛盾 + 一个未解边界

- 0.4 §9.1 明文决策：「候选池**不设上限、全量保留（不截断）**」；
- 但《提炼提示词》§2 模板变量表写：`{{candidates}}` =「标签预过滤后候选池（priority DESC **截断入批**）」——同文档 §3 又写「分批提炼，**不截断**」。**「截断入批」与决策直接冲突**，应为笔误（建议改为「priority DESC 排序入批」）。
- 更深处有一个**未被文档覆盖的逻辑边界**：三条约束——①全量召回、②同一新记忆只进一批、③单次上下文硬限——**当某一条新记忆的候选集本身就超过上下文预算时无法同时成立**。文档未给出该 edge 的兜底（截断该记忆的候选？降级告警？）。建议补一句策略（如：单记忆候选超预算时按 priority DESC 取预算内 top-k，仅此场景允许截断并记 `anomaly_warn`）。

### 2. 接口契约对外 API 仍用中文维度名，与「强制 id」规范冲突

- 《接口契约》`/v1/inject` 的 `custom_filter` 与 `/v1/search` 的 `dimensions` 示例写 `["项目", "技术栈"]`；
- 但注册表 / 模板引擎 / 数据模型均**强制引用 id**（`projects` / `tech_stack`），中文仅作 display_name。
- **对外 API 到底收 id 还是收中文名再过归一化层？** 示例与规范不一致。建议：API 层统一收 id（Agent 读注册表），两处示例改为 `["projects", "tech_stack"]`；或显式声明 API 接受中文名并走归一化（但这会把 LLM 归一化职责泄漏到 Agent 侧，不推荐）。

## 四、一致性小修（🟡 建议顺手对齐）

3. **§16.4 措辞**：模块表 `engine/` 新写列「候选池**采样**」应为「候选池**分批**」（与「不截断、全量召回」决策对齐）。
4. **§13.5 SLO 旧表述**：「主动关怀链路…**信号产出** → SCSM 触发 → …」——v0.4 已删关怀信号，关怀链路起点现为 SCSM 触发器（cron/monitor/数据事件）→ Agent 自查，应改为以「SCSM 触发」为起点的表述。
5. **time_velocity 二值 vs 三类映射未说全**：§8.1 分静态/偏好/动态三类，但 time_velocity 仅 static/dynamic 两值；偏好/模式类（周~月）归哪边未写死，注册表实际取 `static`（无 TTL）。合理，但应在 §8.1 显式声明「偏好/模式类默认 static」。
6. **L2 批大小不一致**：《提炼提示词》写「~20 条/批」，0.4 §9.1 说「本地 64K 可大于底座 20 条」。应对齐为「按当前模型上下文预算」，不写死 20。
7. **L0 增量提炼的「增量段」提取机制未明**：追加后再提炼，L1 如何界定"上次停在哪"？建议明确：按消息时间戳 > `raw_files.refined_at` 提取增量段，或加 `last_refined_seq` 游标（L0 文件格式与数据模型均未指定）。
8. **两版 schema 并存易误读**：《维度标签-schema 草案》的 memories 内联 `archived_memory_id` / `source_message_ids` 字段，《数据模型设计（D8）》已改为独立的 `memory_archive` / `memory_sources` 表（更规范化、更优）。建议给草案标注「已被 D8 取代」，避免照错版本建表。
9. **维度归一化相似度兜底的误标可观测性**：阈值 0.85 自动映射，边界情形可能静默误标到错误维度。`fuzzy_hits` 有计数，但建议 fuzzy 命中也记录「原始名 → 映射目标」供抽检（unknown-drop 路径已告警，fuzzy-hit 路径缺落到条目的审计）。
10. **接口契约缺 SCSM/AgentDispatch 契约**：已在「待后续版本」标注，属已知留白，不计扣分；但 `/v1/inject` 响应 `blocks[].items` 用中文维度名（"身份：…"）作展示是合理的（注入面向人/LLM 读），仅请求侧需统一为 id（见 🔴2）。

## 五、结论与建议

- **总体**：0.4 + 详细设计可进编码，方向与结构无问题。
- **动工前必修**：🔴 1（候选池截断矛盾 + edge 兜底）、🔴 2（API 中文名 vs id 统一）。
- **顺手对齐**：🟡 3–9（均为措辞/示例/声明层面，不动已定决策）。
- **后续版本**：SCSM/AgentDispatch 契约文档、push(SSE) 事件、L1 长会话滑窗分块、提示词 A/B。

*审查完毕。本意见仅指出问题与建议，不代为实现；具体采纳与修改由架构所有者决定。*
