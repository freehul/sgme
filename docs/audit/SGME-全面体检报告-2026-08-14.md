## 2. P0 — 严重（影响稳定性与备份可靠性）

### 2.1 `backup_scheduler` 是连接隔离修复的「漏网之鱼」

**根因链**（已完整定位）：

- 2026-08-11 曾对 `batch_scan.py` 与 `dream.py` 做「线程自建独立连接」修复（其注释明确记载：多调度器线程共享同一 sqlite 连接在 Windows 上存在 access violation 竞态——执行中连接被宿主关闭即原生崩溃）。
- 但 `backup_scheduler.py` **没有同步修复**：`routes_backup.py:73` 仍把宿主连接 `request.app.state.mem_conn / session_conn / wiki_conn` 直接传给备份定时器线程 `ensure_scheduler(...)`，线程体 `_scheduler_loop` 全程复用这些宿主连接做 SQLite backup API 快照。

**实锤证据**：

1. **历史崩溃**：`tmp/sgme-service.err.log` 中成批 `/v1/health`、`/v1/admin/care/scan` 返回 500，堆栈为 `sqlite3.ProgrammingError: Cannot operate on a closed database`（`engine/health.py:104 check_refinement_stalled(session_conn)`），最终 `Application shutdown failed. Exiting.`、进程退出（NSSM 自动重启恢复）。
2. **今日备份失效**：`data/backups/daily_incremental_20260814_040000_c74e7fd2/memory.db` 为 **0 字节**，且 `session.db`/`wiki.db` 未产出（`create_snapshot` 本应三库全备）——`src_conn.backup(dst_conn)` 在失效连接上抛异常，`_backup_db` 只留下空文件。

**修复建议**：`backup_scheduler._scheduler_loop` 改为线程自建连接（对齐 `batch_scan.py:224` 的 `db_mod.init_databases(data_dir)` 模式），不再接收宿主连接；`ensure_scheduler` 签名改为接收 `data_dir` 而非连接。修复后跑 `test_backup.py` / `test_routes_backup.py` 回归。

## 3. P1 — 重要

### 3.1 全量 pytest 3 个失败（配置改测试没同步）

`commit 81a00cf`「revert: 撤销 F-2 lm-studio 降级链兜底（用户决策纠正）」从 `config/llm.yaml` + `config/providers.yaml` 移除了 lm-studio，但 3 个测试未同步更新：

| 失败测试 | 断言 |
|---|---|
| `tests/test_config.py::test_llm_config_has_refinement_chain` | `len(链) >= 3`，实际 2（deepseek + rule） |
| `tests/test_providers.py::test_load_providers_default_file_has_deepseek_and_lmstudio` | providers 必须含 `lm-studio` |
| `tests/test_providers.py::test_real_config_memory_structure_compatible` | 第二链 `provider == "lm-studio"`，实际 `"rule"` |

**违反 AGENTS.md 验收纪律「改动必须 pytest 全绿」**——该配置变更未跑全量测试即提交。

**修复建议**：3 个测试断言改为「2 链 + 无 lm-studio」的新契约（或改为断言「首链 deepseek + 末链 rule drop_batch」的语义，避免再因链长变化脆弱化）。

### 3.2 AGENTS.md 架构铁律 #9 与 config 漂移

铁律 #9 仍写「deepseek → lm-studio（qwen/qwen3.5-9b，:1014，离线兜底）→ rule drop_batch」，但 `llm.yaml` / `providers.yaml` 已移除 lm-studio（2026-08-14 用户决策：提炼统一走云端 DeepSeek）。违反铁律 #12「文档是第一公民」。

**修复建议**：铁律 #9 同步为「deepseek（deepseek-v4-flash，1M 窗口，主模型）→ rule drop_batch」，并同步 `docs/design/SGME-架构设计-v0.9.md` §24 降级链章节。

### 3.3 孤儿文件（raw_files 索引不一致）

`raw/sessions/bd44122f-29f3-426f-9978-70d10a1255a2.md`（`t43-e2e-session`，agent_id=`test-agent-model`，T-43 测试残留，2026-08-13 22:39）：磁盘存在但 `raw_files` 表无记录 → **永远不被提炼**。
