## 一、文档缺口（README 没说的必知项）

### 1.【高】README 快速开始不给默认 API Key，新手启动后无法调通任何 API
- **描述**：README Quick Start 只说"生产必设 `SGME_ADMIN_KEY / SGME_AGENT_KEY / SGME_BEARER_TOKEN`"，**没有提开发默认值**（`dev-admin-key-change-me` / `dev-agent-key-change-me`，藏在 runbook §3）。`sgme/__main__.py` 注释明确"不设则用 dev 默认 + 告警"，README 也未告知这一行为。新手 clone→venv→启动后，对着 runbook §5.2-5.5 示例里的 `your-agent-key` 无处下手，或误以为必须先生成生产 key。
- **建议**：README Quick Start 增加一行"开发模式默认 key（仅本机）：admin=`dev-admin-key-change-me`，agent=`dev-agent-key-change-me`，生产必须覆盖"，并链接 runbook §3。

### 2.【高】runbook 与实际配置严重脱节（LLM 主链 / 模型 / 向量 embedding 全部过时）
- **描述**：实测运行中服务 `llm.provider=deepseek, model=deepseek-v4-flash`；`config/llm.yaml` 主链为 deepseek 第一、lm-studio 第二、rule 兜底。但 runbook：
  - §4.2「生产模式（接 LM Studio）」示例把 `lm_studio(qwythos-9b-v2-i1)` 放第一位，模型名还是已废弃的 `qwythos-9b-v2-i1`（实际是 `qwen/qwen3.5-9b`）；照抄会覆盖正确降级链。
  - §12.2 向量模型写 `text-embedding-nomic-embed-text-v1.5`（LM Studio），实际 `config/sgme.yaml` 已是火山方舟 `doubao-embedding-vision`（`api/plan/v3` 通道，`VOLC_API_KEY`）。
- **建议**：runbook 对齐现状（deepseek 主链 + 火山 embedding），或明确标注示例为旧版并在顶部标注"以 config/ 下实际配置为准"。

### 3.【中】append 的 content 格式（L0 消息块）只在一个示例里出现，新手极易写错
- **描述**：`content` 必须是 `# {ISO} {role}\n...` 的 L0 格式，仅 runbook §5.2 一个示例展示；README 完全没提。实测传纯文本（`content="我叫王小明…"`）得到 400 `content 解析出 0 条消息（需 # {ISO} {role} 格式）`——报错说了要什么格式，但没给示例，新手需要去翻 L0 文件格式设计文档。
- **建议**：README / runbook 用独立小节说明 L0 content 格式（含最小完整示例：`# <ISO> user\n<内容>` + `# <ISO> assistant\n<内容>`），并解释 session_key / started_at 语义。

### 4.【中】"双库 vs 三库"表述自相矛盾，且 runbook 数据目录表漏了 session.db
- **描述**：README 简介与 AGENTS.md 说"双库（memory.db + wiki.db）"；README 目录结构却说 `data/` 是 "three-DB connections (memory/session/wiki)"；runbook §7 数据目录表只列了 memory.db / wiki.db，**漏掉实际存在的 `data/session.db`**（raw_files 索引就存在 session.db，queue_depth 也查它）。
- **建议**：统一术语（如"三库 + 文件"），runbook §7 补 session.db 并说明三库职责。

### 5.【中】环境变量表不完整、标注失实
- **描述**：runbook §3 表只有 5 个变量，缺：`VOLC_API_KEY`（向量 embedding 必需，见 B1）、`SGME_MCP_PORT` / `SGME_MCP_DISABLED`（§8.1 正文有但表没有）；且 `DEEPSEEK_API_KEY` 标注为"降级链用"，实际它是**主链（第一位 deepseek）必需**，不设则提炼直接 401→lm-studio→drop_batch（日志与 refine_runs 均有真实记录）。
- **建议**：环境变量表按"主链必设 / 可选"分组补全，DEEPSEEK_API_KEY 改标"主链必设（refinement 第一优先 deepseek）"。

### 6.【低】runbook §1 环境要求"依赖"列不全
- **描述**：只列 FastAPI/uvicorn/pyyaml/httpx/pytest，缺 numpy / sqlite-vec / requests / mcp / jieba（均为 pyproject.toml 主依赖）。
- **建议**：改为"依赖见 pyproject.toml，`pip install -e .[dev]` 一次装齐"。

### 7.【低】docs/ 目录混杂大量内部过程文档，新手不知道该读什么
- **描述**：docs/ 下有 audit/ decisions/ plans/ research/ reviews/ 等目录；README 的 Design Docs 表只覆盖 design/ 下 5 篇，未说明"新用户只需读 runbook.md + 架构 v0.9"。
- **建议**：README 增加"新用户阅读路径"小节（runbook → 架构设计 → L0 格式）。

## 二、流程断点（照着文档走会卡在哪）

### 1.【高】向量检索静默降级，health 完全看不出来（配置缺失无感知）
- **描述**：实测 `/v1/search` 的 `meta.routes` 只有 `['bm25']`。根因：`config/sgme.yaml` 向量模型已切火山方舟，但运行环境 **`VOLC_API_KEY` 未设置**，日志每轮 `embed: api_key_env=VOLC_API_KEY 未设置` + embeddings 401，向量一路降级。文档吹的"BM25+向量+RRF 混合检索"对新手实际只剩 BM25；而 `health` 里 `llm.available=true` 只反映提炼链，**不暴露向量不可用**，新手无从排查（除非翻日志）。
- **建议**：health 增加 `vector/embedding.available` 字段；runbook 在"验证命令"里写明向量检索前置条件（VOLC_API_KEY + 网络可达），并给出 routes 应包含 `['bm25','vector','rrf']` 的判定。

### 2.【高】inject 返回 200 但 block 为空，且无任何解释——流程最后一步得到"空画像"
- **描述**：实测 append"我叫胡亮，是一名独立开发者" → refine 成功（priority=90，memory_tags=identity+skills）→ `POST /v1/inject` mode=daily 返回 200，但"👤 基本信息"`items=[]`、`present=false`（"🔥 当前状态"也只显示了库里另一条带 focus 维度的历史记忆）。根因：`templates/daily.yaml`"基本信息"section 查询 `dimensions:[identity,family]` 且默认 `match=all`（需同时命中 identity **和** family），单条 identity 记忆被过滤。这是模板语义问题而非 bug，但**响应没有任何提示**告诉新手"为什么空、需要什么维度的记忆"，新手会以为记忆丢了或引擎坏了。
- **建议**：inject 对空 section 返回提示（如 `"reason": "缺少 family 维度记忆（需同时命中 identity+family）"`）；文档补充模板查询语义（match all/any、priority_min、TTL、time_window）与"为什么可能为空"。

### 3.【中】LLM 全挂时 refine 长时间无反馈（真实发生过 4-8 分钟失败）
- **描述**：日志显示历史上 deepseek 401（key 未配/配错）快速失败 → lm-studio timeout 120s×2 → 降级 rule `drop_batch`，refine_runs 记录 `status=error, "全链降级失败，drop_batch"`。整个过程单次 refine 可拖 4-8 分钟（lm-studio 超时占大头），新手配错 key 会以为服务卡死，且文档没有"失败可能很慢"的预期说明。
- **建议**：refine 前先暴露 LLM 可用性（health 已有 llm.available，但新手不会先查）；runbook 常见问题补"为什么 refine 要等好几分钟才失败"及 `timeout_s/max_retries` 的调法。

### 4.【中】两个 e2e 冒烟脚本并存，文档未说明差异，新手不知道该跑哪个
- **描述**：runbook §5.6 `python scripts/e2e_smoke.py`（进程内 mock LLM，monkeypatch L1/L1.5，**不需要服务在跑**）vs §5.7 `scripts/e2e_smoke_v04.py`（需要 Gateway 已启动 + 真实 LLM + `--admin-key/--agent-key` 参数）。README 一个都没提。新手按 5.6 跑、或按 5.7 漏传参数，都会困惑。
- **建议**：文档明确两者区别（mock 自检 vs 真实链路冒烟），建议只保留并推荐 v04 作为"真实链路验收"，或统一说明。

### 5.【中】append 不会自动提炼，新手误以为记忆已入库
- **描述**：`config/sgme.yaml` `refine_on_append: false` + `batch_scan.enabled: false` → append 后文件停在 `status=new`（health `queue_depth=1`），必须手动 `refine/trigger` 才提炼。runbook §5.2→5.3 演示了手动链路，但没有一句话明示"append 后不会自动提炼"。
- **建议**：runbook 在 §5.2 加一句"append 仅写入 L0，需手动触发 refine（默认不自动提炼）"，并顺带解释 queue_depth 含义。

### 6.【低】Windows 服务安装脚本硬编码本机路径，换机必失败
- **描述**：`scripts/install_sgme_service.bat` 硬编码 `<用户目录>\AppData\Local\Microsoft\WinGet\Packages\...\nssm.exe` 与 `<项目目录>\.venv\Scripts\python.exe`。README/runbook 声称"管理员运行即装好"，但脚本不检测/安装 NSSM、不按脚本位置推导项目路径，其他用户/目录运行必失败。
- **建议**：脚本改为探测 NSSM（`where nssm` / winget install）、用 `%~dp0..` 推导项目路径，并在失败时给出可读提示。

### 7.【低】tmp/ 目录 clone 后不存在
- **描述**：`.gitignore` 排除 `/tmp/`，clone 后无此目录；但 runbook §7 数据目录表、README 服务化部署节均引用 `tmp/sgme-service.log` 等。新手按文档找 tmp 找不到（首次启动/安装时才创建）。
- **建议**：文档注明"tmp/ 由运行时自动创建"。

## 三、错误信息不友好处

### 1.【中】403 鉴权错误无引导
- **描述**：实测 403 原文：`缺失或无效的 X-API-Key（Agent）`、`缺失或无权限的 X-API-Key（需管理员）`（用 agent key 调 `/v1/admin/*` 时）。没有提示：默认 key 是什么、admin 与 agent 是两把不同的 key、在哪配置。
- **建议**：错误信息追加引导（如"开发默认 key 见 runbook §3；admin/agent 为两把 key，refine 需 admin"）。

### 2.【中】inject 未知 mode 暴露内部绝对路径、不列出可选值
- **描述**：实测 `{"mode":"morning"}` → 400 `模板加载失败: 模板文件不存在: D:\Projects\SGME\templates\morning.yaml`。新手不知道可选 mode，还看到服务端绝对路径。
- **建议**：报错改为"mode 必须为 daily/coding/work/full（或提供 custom_filter）"，不暴露内部路径。

### 3.【低】请求体校验 422 与业务错误风格割裂
- **描述**：缺字段时返回 FastAPI 默认英文 Pydantic 错误（`"Field required"` + `loc` 数组 + 原始 input 回显），与全系统中文 `ERR_*` 风格不一致。
- **建议**：统一为中文 `{"error":{"code":"ERR_INVALID_ARGS","message":"缺少必填字段: session_key"}}` 风格。

### 4.【低】append content 格式错误无示例（同文档缺口 3）
- **描述**：400 `content 解析出 0 条消息（需 # {ISO} {role} 格式）` 未附示例。
- **建议**：报错信息带一行最小示例。

## 四、配置不明确处

### 1.【高】VOLC_API_KEY 是当前向量检索的硬前提，却几乎无文档
- **描述**：`config/sgme.yaml` `search.vector.api_key_env: VOLC_API_KEY`（注释还注明"daemon 服务环境需注入"），但 runbook 环境变量表、README 均未提。未设置时向量全程 401 静默降级（见 B1）。另外：NSSM 服务化部署下环境变量如何注入（服务以 LocalSystem 运行）也没有任何文档。
- **建议**：环境变量表补 VOLC_API_KEY 并标注"向量检索必设"；runbook 服务化章节补"NSSM 服务环境变量注入"说明。

### 2.【中】大量配置项在入门文档中完全未展开，占位符易误导
- **描述**：`config/sgme.yaml` 里 dream（夜间整理）、skills_hub（`remote.source: "user@nas-host:/path/to/skills-hub.git"` 是占位地址）、backup.remote_dir（`E:\SGME_Backup` 是本机路径）等。新手翻配置文件会以为这些都必须配、或误以为 NAS 占位符是真实地址。
- **建议**：配置文件对占位项加"非必配/示例"注释；README 增加"默认配置即可跑通最小闭环，扩展模块按需开启"说明。

### 3.【低】命令假设 `python` 在 PATH，Windows 下应为 `.venv\Scripts\python.exe`
- **描述**：README/runbook 大量使用裸 `python -m sgme` / `python scripts/...`，未提示 Windows 下需先激活 venv 或使用 `.venv\Scripts\python.exe`；本机实际进程也是绝对路径解释器启动。
- **建议**：文档统一示例为 `.venv\Scripts\python.exe -m sgme`（Windows），并提示先激活 venv。

## 五、综合结论

- **链路本身**：最小闭环（append→refine→search）真实可用，DeepSeek 提炼、L0 落盘、溯源 trace、queue_depth 水位均与文档一致，基础工程质量在线。
- **新手体验主要瓶颈**：① 文档（尤其 runbook）滞后于实际配置，主 LLM/向量 embedding 两处"照着配必错"；② 两个"静默降级/静默为空"（向量检索 401 降级、inject 空 block）在 API 响应里无任何提示，新手无法自愈；③ README 不提供默认 key 与 L0 content 格式，跨过第一道门槛需要先看 runbook 且要自己拼装信息。
- **优先修复建议**（按性价比）：runbook 对齐现状（问题 2/5）→ health 增加 vector 可用性 + inject 空 block 提示（B1/B2）→ README 补默认 key 与 L0 格式（1/3）→ 错误信息引导与 422 统一（三-1/2/3）。
