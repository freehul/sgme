# 任务
从会话里提取**该长期保存的、属于用户的事实**。顺序：先**取证**（这段内容归谁）→ 再判 route → 最后填字段。

# 一、取证：一段话到底归谁（最容易错的一步）
**不要按"谁打的字"判归属，要按"这段内容是谁提供的"判。**

| 情形 | 归属 | 怎么判 |
|---|---|---|
| 用户自己说/写 | **用户** | 用户轮里的第一人称陈述 |
| 用户只写"帮我润色/翻译"，正文由助手改写成稿 | **用户** | 改写文本与用户上一轮措辞**大量重合**（同名人名、地点、数字、事件细节）→ 细节是用户提供的 |
| **用户主动提问，助手给出直接答案**（属性/参数/结论/做法/可行性） | **用户** | 只抽答案本身，不抽"用户询问了 X"这个动作 |
| 助手在用户内容之外**主动新增**的科普/解释（**用户没问**） | **助手** | 一律不进记忆池（`route=discard` 或 `wiki_candidate`） |
| 用户贴来翻译/润色的**他人**文字 | **他人** | `subject=others:<来源或 unknown>`，不得写成用户偏好 |

⚠️ 最常见的三个错：① 只记"用户询问了 X"、丢掉答案 Y；② 用户只说"帮我润色"，正文在助手输出里 → 误判为助手内容整段丢弃；③ 用户问一句、助手答六段 → 把科普当事实存进记忆池。

# 二、route（来源判定，只看来源不看"信息量大不大"）
| route | 判据 | 典型 |
|---|---|---|
| `memory` | 内容归属用户的（含助手改写用户草稿、助手复述用户偏好且用户未否认） | 用户陈述自己的偏好/习惯/经历/身体状况 |
| `skill_candidate` | 可复用的方法与经验（做事步骤、踩坑解法、排障流程） | "长会话要按段落分块再提炼" |
| `wiki_candidate` | 客观知识、调研结论、参数表（**用户没主动索取的**）；用户主动问了就归 memory | "多伦多靠社区规划保留族裔街区" |
| `discard` | 寒暄、礼貌应答、工具回灌、系统注入、临时状态播报、与用户无关的闲聊 | "很高兴帮你！""测试跑了 10 分钟" |

# 三、输出结构（2.0 硬性结构，逐字段照填）
只输出一个 JSON 数组，每个元素是**一个单元**：

```
{
  "main_event": {"content": "<主干：这件事/这条信息的完整表述，≤200字>",
                 "occurred_at": "<粗日期展开成区间，如 2020~2023；说不清写 null>",
                 "feeling": "<用户的感受；没有写 null>"},
  "facts": [
    {"type": "<七值：约束/习惯/偏好/状态/事实/经验/想法>",
     "content": "<一条一个事实点，≤100字>",
     "subject": "<self / others:<姓名或身份> / unknown>",
     "certainty": "<confirmed/tentative/discussing>",
     "derivation": "<fact/reconstructed/inferred>",
     "modality": "<done/planned/wished/quoted/unknown>",
     "occurred_at": "<该事实自己的时间锚；与主干同则 null>"}
  ],
  "causes": [{"from": "<原因>", "to": "<结果>"}],
  "trait": "<从行为里看出的性格特质，只给原文短语 ≤50字；没有写 null>",
  "dimensions": {"primary": "<维度id，必填唯一>", "secondary": ["<id>", "<id>"]},
  "route": "memory | skill_candidate | wiki_candidate | discard"
}
```

规则：
- **`facts` 逐条列，一条一个事实点**——不要合并成一条塞多个事实；拆不拆成独立记忆由下游规则判定，你不做这个决定。
- 事实上限：一条单元 ≤6 条 `facts`；`secondary` 最多 2 个。
- `type` 七值判据见第四节；`subject` 必填（别人说过的"我"≠ 用户）。
- **不要输出** `memory_type`、`priority`、`subject/predicate/object` 三元组——2.0 不用这些字段。
- 反例（无内容可存）输出 `[]`。

# 四、七值 type 的正反对照
1. `约束` = 用户定的必须遵守的规则（"删除一律走回收站"）；`状态` = 当下身心情绪（"按时吃药仍疲惫"）。❌ 把疲惫标成约束。
2. `习惯` = 做法/流程（"先研究需求再选方案""每月去诊所复查"）；`偏好` = 喜欢讨厌（"喜欢傍晚散步"）。❌ 把流程习惯标成偏好。
3. `想法` = 讨论中没定（"考虑报个线上课"）；`事实` = 客观信息；`经验` = 发生过带教训的事。❌ 把"我在考虑"标成事实。
4. **中性偏好也要抽**（"我周末喜欢逛旧书店"），不许以"不重要"为由丢。

# 五、什么不是记忆（实测误存 10%，全是这三类，逐条排除）

**判据：一条记忆必须「半年后还对用户有用」。** 下面三类一律**不产出单元**：

1. ❌ **过程叙述**——"用户询问了 X，助手尚未作答""用户先叫停了，随后指示…""助手完成调研后回复"。
   只有**结论**才是记忆，过程不是。改法：对话有结论 → 只记结论；没结论 → **整段不记**，不要写"尚未作答"。
2. ❌ **执行痕迹**——提交号、文件行数、目录变更、版本号 bump、日志耗时。
   例："SGME 554cb6b、WinUse 6cb5240，各 3 文件 +84 行" → 不记。
   例外：用户**明确要求记住**某个编号（"记住这个 commit 是回滚点"）才记。
3. ❌ **同义重复**——同一件事换措辞说两遍（"approval policy 已由 ask 改为 never" vs
   "用户将 approval policy 从 ask 改为 never"）。一段对话内同一事实**只出一条**。

# 六、软遗忘（最高优先级）
用户说"别记得 / 忘掉 / 别再提 / forget / do not remember X"：
- 输出一条单元：`route=memory`，`main_event.content` 用固定句式
  "User asked that a certain topic no longer be actively mentioned"(中文会话写"用户要求不再主动提及某主题")
  ——**正文不得复述被忘的内容**
- 另加字段 `forget: {"topic": "<主题概括，原样保留不压字数>", "kind": "preference|event|detail"}`
- **边界（防假阳性）**：只有用户**明确表达"以后别再提/忘掉这个话题/不要记住这件事"**才算。
  - ✅ 算："以后别提 X 了""把 X 忘掉""这事不要再记着"
  - ❌ 不算（按普通事实处理）：删除文件/目录/项目、抱怨某事、"这个方案不行"、"不想聊这个"（临时转话题）、"把这个记录删掉"（数据操作）
- 识别不到遗忘请求 = 任务失败。

# 七、输出要求
- 只输出一个 JSON 数组，无解释、无 markdown 代码块。
- **专名、数字、地点、限定语原样保留**（"wild rubber from the Amazon" 不得写成"环保材料"）。
- 语言 = 会话原文语言，逐条自检。
- 空数组 `[]` 合法。

# 再次强调
1. 结构：一个单元 = 主事件 + 事实列表 + 因果 + 特质 + 维度 + 路由。
2. 助手改写用户草稿里的细节归用户（`derivation=reconstructed`）；助手额外补的科普归助手（`discard` / `wiki_candidate`）。

4. 推断必须标 `inferred`（"早晨读数偏高、按时吃药" ≠ "正在服用降压药"）。
5. 遗忘请求必须识别，正文不含被忘内容本体。
6. 不记过程叙述、不记执行痕迹、同一事实只出一条——三条都过才算合格。
